# Развёртывание RampPulse для конкурса

Эта конфигурация поднимает общий web/backend для нескольких участников на одном VPS
и публикует его через временный HTTPS Quick Tunnel. Она рассчитана на демо с
вымышленными данными, не на промышленное использование.

## Что потребуется

- Ubuntu Server 24.04 LTS;
- публичный IPv4 и SSH-доступ по ключу;
- исходящее HTTPS-соединение.

Свой домен для временного демо не нужен: Cloudflare выдаёт HTTPS-адрес на
`trycloudflare.com`. Адрес временный и может измениться после перезапуска туннеля.
Туннель проксирует HTTP и WebSocket к FastAPI.

## Установка

Распакуй архив проекта на сервере, перейди в корень проекта и запусти от root:

```sh
bash deploy/install_server.sh
```

Скрипт ставит зависимости, устанавливает unit-файлы и запускает backend и туннель.
SQLite хранится в `/var/lib/ramppulse`; backend запускается одним worker, потому
что состояние симуляции пока находится в памяти процесса.

Временный HTTPS-адрес появится так:

```sh
journalctl -u ramppulse-tunnel -f
```

Открой адрес с `/login` и проверь вход диспетчера и инженера, чат и звонок между
двумя устройствами. Для конкурса включён `DEMO_MODE=1`, поэтому доступны
демонстрационные учётные записи. Не загружай реальные персональные данные.

## Ограничения

WebRTC передаёт звук напрямую, если сети позволяют. Для сетей с жёсткими
ограничениями потребуется coturn и выдача временных TURN-учётных данных; в этой
конфигурации TURN пока не включён.

Для установленного Tauri-клиента после получения адреса Quick Tunnel пересобери
пакет с этим адресом, например:

```sh
RAMPULSE_SERVER_URL=https://random-name.trycloudflare.com npm run desktop:build
```

Такая сборка открывает RampPulse в своём окне и подключается к общему VPS вместо
запуска локального сервиса. Если временный адрес туннеля изменится, desktop-пакет
нужно пересобрать с новым адресом. Для стабильного адреса позже можно подключить
бесплатный или собственный домен.
